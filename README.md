# beamio-UI

The consumer web application of Beamio: a React and TypeScript progressive web app (PWA). The same UI is embedded in the Beamio iOS and Android shells as their shared user interface.

- Application: [beamio.ca/app/](https://beamio.ca/app/)
- Website: [beamio.ca](https://beamio.ca/)
- Repository: https://github.com/CoNET-project/beamio-UI

## What this repository is, and is not

This repository contains the **consumer PWA** and the UI that the iOS and Android shells load. It does not contain:

- Beamio POS (the merchant point-of-sale terminal),
- Beamio Merchant OS (the merchant operations console),
- the native shell projects for iOS and Android,
- backend services, operator tooling, or smart contracts.

Those components live in other places and have their own release processes. A change in this repository does not by itself replace a native SDK or a store binary.

## Features

These features exist in the source tree. Availability depends on the deployed version, the native bridge, and the service configuration.

- Wallet access: creation, recovery, and account management flows.
- Payments in USDC and merchant-issued store credit (shown as Service Credits), including balance views.
- Merchant discovery, memberships, vouchers, and rewards pages.
- Messaging through the CoNET Chat SDK (vendored in `vendor/conet-chat-sdk`), with OpenPGP-based message handling.
- Voice call screens and call signalling through the CoNET Chat transport.

**CoNET Chat does not use WebRTC.** Call media and signalling go through the CoNET Chat transport. This repository contains no WebRTC code.

## Architecture

- React 18 with TypeScript, built with Create React App and CRACO (`craco.config.js`).
- Ethers v6 for blockchain reads and signing flows.
- IndexedDB and PouchDB for local persistence.
- Web workers for background tasks (`src/workers/`).
- OpenPGP 6 for message encryption and key handling.
- The CoNET Chat SDK as a local package (`file:./vendor/conet-chat-sdk`).

In the browser the app runs as a normal PWA. Inside a native shell, the same bundle runs in a WebView and reaches native features through a bridge. Storage and bridge boundaries differ between the two runtimes. A storage or network failure must stay distinguishable from a confirmed empty account.

## Requirements

- Node.js: the checks in this README were run with **Node.js 22.23.3** (npm 10.9.9), which is inside the `engines` range `>=18 <24` in `package.json`. Use that version. `.nvmrc` names **20**, which has **not** been verified for this repository.
- npm with `package-lock.json` (the lockfile for the commands below).
- `yarn.lock` is also present, because `package.json` declares `packageManager: yarn@1.22.22`. The yarn route has not been verified; use npm.
- The lockfile resolves 1,455 packages through `registry.npmmirror.com`, a public npm mirror, and 312 packages through `registry.npmjs.org`. The lockfile is kept as it was in the source revision.

## Install and run

```bash
git clone https://github.com/CoNET-project/beamio-UI.git
cd beamio-UI
nvm install 22.23.3           # the version used for the verified checks (requires nvm)
nvm use 22.23.3
npm ci --legacy-peer-deps
npm start                     # development server
```

`npm ci` without `--legacy-peer-deps` stops with `ERESOLVE`: the peer range of `@craco/craco@7.1.0` does not accept the locked `react-scripts@5.1.0-next.26`. The lockfile installs cleanly with the flag.

The CoNET Chat SDK is a local dependency (`file:./vendor/conet-chat-sdk`). Its build output in `vendor/conet-chat-sdk/dist` is not stored in this repository. `npm ci` builds it through the SDK's `prepare` script.

Local development needs no production secrets. Use disposable test accounts, not a personal wallet.


In the verified run, 2,029 tests pass and 2 are skipped (2,031 in total) across 234 suites (233 pass, 1 suite skipped). This snapshot omits 28 test files and 11 fixtures (see "Testing: what is not included yet"), so the count is lower than in the internal source revision.

## Builds

| Command | Output | Use |
|---|---|---|
| `npm run build` | browser build, public path `/app` | web deployment of the PWA |
| `npm run build:shell-embedded` | embedded build, public path `/`, shell flag on | UI package for an iOS or Android shell |
| `npm run build:shell-qa-embedded` | embedded build with `REACT_APP_PGP_IDENTITY_CREATE_ENABLED=true` | QA candidate for shells; not a production build |

Build output goes to `build/`. Source maps are generated by default.

## Configuration

The build reads these public variables. None is a secret.

| Variable | Meaning |
|---|---|
| `REACT_APP_SHELL_BUILD` | `true` for a shell (embedded) build |
| `REACT_APP_PGP_IDENTITY_CREATE_ENABLED` | `true` only for QA builds |
| `PUBLIC_URL` | public path, set by the build scripts |

The repository ships no `.env` files. Never put secrets in any `.env` file.

Source publication, QA acceptance, device acceptance, web deployment, and store submission are separate stages. A public commit or a successful build does not establish any of the later stages.

## Shell UI package

Each shell embeds exactly one UI ZIP, and the iOS and Android shells must use the same ZIP bytes for a given release:

1. Build with `npm run build:shell-embedded` (or the QA variant for QA).
2. Remove the source map files (`*.map`) and the trailing `sourceMappingURL` comment lines from the JavaScript and CSS files before the package is made. The repository does not ship a script for this step.
3. Record the source commit, the PWA version, and the SHA-256 of the ZIP.
4. Embed the same file in both shells and verify its SHA-256 in each finished application.

## Contributing

Open an issue with the runtime (browser or shell), the application version, the expected and actual behavior, and reproduction steps. Submit focused changes against `main`, and run the tests and the type check before you open a pull request.

Do not include wallet secrets, recovery codes, test-account credentials, signing keys, or private service configuration in issues, pull requests, or commits. Automated tests must not use real account data, keys, or recovery material.
